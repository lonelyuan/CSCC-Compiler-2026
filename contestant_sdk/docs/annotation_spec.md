# 标注语义规范

评测系统当前只认可“语义保持”的源码标注。若参赛者提交了标注后的 baseline 源码，
judge 会先移除允许的标注语法，再与官方 baseline 逐文件比对；若移除标注后仍有任何差异，
提交会被判为非法修改源码。

当前允许的标注语法只有以下三类：

- `#pragma compiler2026 ...`
- `[[clang::annotate("...")]]`
- `__attribute__((annotate("...")))`

额外约束：

- 只允许在官方 baseline 对应源码副本上添加这些标注，不允许改写已有 token
- 不允许通过新增宏头文件、辅助包装函数、额外 include 或条件编译来间接修改 baseline 语义
- 允许空白符和普通注释差异，但不允许除上述标注语法外的其他代码变化
- 提交标注后源码时，路径应放在 `submission_dir/src/baseline/`

允许的标注用途：

- 标识可并行区域
- 提示无副作用函数
- 标记运行时图构建边界

禁止的标注用途：

- 传递特定测试用例的矩阵规模
- 硬编码线程数、绑核策略或平台特定调度参数
- 传递任何可用于预计算打表的信息

参赛者若使用标注，必须在设计文档中说明：

- 标注放置位置
- 标注对 Pass 的影响
- 标注不会泄露测例信息的理由
