## 核心目标

赛题要求在 LLVM 中通过新增 Pass 分析给定应用程序的算子依赖关系，生成二进制可执行程序，在结果通过双精度误差检验的前提下，最大化并行计算性能。

参赛对象是分块 Cholesky 分解。需要让原始程序中的 `cholesky`、`trsm`、`madd` 算子在鲲鹏 920 ARM 平台上高效并行执行。

## 允许事项

- 仅限在 LLVM 层面增加 Pass 做算子依赖分析和可执行程序生成。
- 必须面向鲲鹏 920 ARM 平台构建编译 Pass。
- 可以对给定应用程序源代码加入标注辅助 LLVM Pass 分析，但标注语义必须在文档中规范描述。
- 可以自行设计和实现并行运行时库，供编译器插入接口调用；运行时接口也需要在文档中规范描述。
- 可以参考或使用符合开源协议的软件模块，但必须在设计文档和源代码头部明确说明。

## 禁止事项

- 不可通过修改算法源码获取性能提升，标注除外。
- 不可修改、重定义、替换或绕过 `cholesky`、`trsm`、`madd` 算子实现获取性能提升。
- 性能提升应来自对 `cholesky`、`trsm`、`madd` 的依赖分析与并行执行，而不是改写官方算子或测试流程。
- 必须严守学术诚信；代码抄袭或未说明借用可能取消资格。

## 功能测试

评测系统把提交的 LLVM Pass 和运行时库集成到毕昇编译器后，编译官方原始程序并运行不同维度的测试矩阵。

输出矩阵通过双精度误差检验则该测试点通过。

功能分规则：

- 所有测试点未通过：0 分。
- 所有测试点通过：100 分。
- 部分测试点通过：按通过比例计算，并有非线性加权。
- 通过率门槛是 90%。低于 90% 时计 0 分，且不能获得性能得分资格。

## 性能测试和评分

性能测试只统计通过正确性检验的用例，并只精确统计核心计算函数执行时间，排除文件 I/O 与结果校验开销。

性能评价采用几何平均加速比：

```text
speedup_i = T0_i / T_i
geo_speedup = (product(speedup_i for passed cases)) ** (1 / passed_case_count)
performance_score ~= 100 * geo_speedup / m_ideal
```

其中 `T0_i` 是分块 Cholesky 算法在鲲鹏 920 平台上的单核串行执行时间，`T_i` 是参赛程序时间，`m_ideal` 是预设理想单核效率折算系数。测评日志中可能显示为 `m_ideal=128.0`，此时约 `2x` 几何平均加速只对应 `1.56` 左右的性能分。

初赛总分权重：

- 通过率：40%。
- 性能得分：60%。

因此，若功能满分且 `m_ideal=128`，总分近似为：

```text
total_score = 40 + 0.6 * (100 * geo_speedup / 128)
```

## 算法背景

赛题背景是动态算子图编译与并行调度。静态算子图拓扑在编译时固定，适合一次性下发到设备侧执行；动态算子图拓扑会随运行时输入变化，Host 侧不断更新和下发图会产生额外开销。

动态拓扑常见来源：

- batch size 或输入序列长度变化。
- 输出 shape 与输入数据相关。
- 稀疏张量、不规则张量、图神经网络等场景。

Cholesky 分解可以被看成动态算子图示例：矩阵规模变化时，朴素 Cholesky 和分块 Cholesky 对应的算子图拓扑也随之变化。

## 分块 Cholesky 依赖结构

PDF 给出的分块 Cholesky 主结构：

```c
for (int i = 0; i < n; i += b) {
    cholesky(&A[i * n + i], &L[i * n + i], i_dim, n);
    for (int j = i + b; j < n; j += b) {
        trsm(&A[j * n + i], &L[i * n + i], &L[j * n + i], i_dim, j_dim, n);
        for (int k = i + b; k < n; k += b) {
            madd(&L[j * n + i], &L[k * n + i], &L[j * n + k], j_dim, k_dim, n);
        }
    }
}
```

关键依赖：

- `cholesky(panel)` 产生当前对角块。
- `trsm(row, panel)` 依赖当前 panel 的 `cholesky(panel)`。
- `madd(row, col, panel)` 依赖对应的 `trsm(row, panel)` 与 `trsm(col, panel)` 输出。
- 下一 panel 的 `cholesky(panel + 1)` 只需要等待影响该对角块的更新完成，不必理论上等待所有 trailing matrix 更新；这是跨 panel DAG 的核心优化空间。

## 工程启示

- 当前项目路线应继续保持 LLVM Pass 分析和 runtime 调度协同，而不是函数级替换或官方算子改写。
- Pass 需要恢复 block 坐标和读写关系，生成可解释的依赖边。
- runtime 应保持通用任务调度角色，只执行 Pass 生成的 task function，不理解或重写算子语义。
- 高分需要显著提高几何平均加速比；`m_ideal=128` 下，`2x` 左右加速对总分贡献很有限。
- 决赛文档和答辩占比较高，设计文档必须持续记录约束遵守、依赖分析、调度设计、性能数据、瓶颈和对比。
